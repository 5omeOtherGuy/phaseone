# ADR-0102: Run the gate and task builds on Depot CI alongside GitHub Actions

## Context

The owner signed the fleet up for Depot CI and, on 2026-09-29, chose to migrate phaseone's GitHub Actions workflows to it (issue #479). Depot's migration tool copies `.github/workflows/` into `.depot/workflows/`; Depot CI runs the copies on its own runners and leaves GitHub Actions untouched.

## Decision

This supersedes ADR-0011, whose "one job, no other workflows" no longer holds; its core stays in force: `scripts/gate.sh` is the single definition of green, the required check on `main` is GitHub Actions' `gate`, and red-first suites stay on their task branch so `main` is always green. `.depot/workflows/` holds `ci.yml` (the gate) and `build.yml` (task-branch builds), generated by `depot ci migrate workflows`; the only change is `runs-on: depot-ubuntu-latest`. `release.yml` is not migrated: release publication stays on GitHub Actions only.

## Consequences

Every PR, main push and `task/**` push runs the gate or build twice, once on GitHub and once on Depot, which uses Depot minutes. GitHub Actions stays the source of truth: branch protection's required `gate` check, `scripts/ci-build.sh` and `release.yml` all still read GitHub's runs. An edit to a workflow in `.github/workflows/` must be mirrored in `.depot/workflows/` until one of the two is retired. Keeping `release.yml` off Depot avoids two runners racing to publish the same `main-<sha>` release, whose byte-identical rerun check would fail if their release builds differ.

## Alternatives considered

Migrating `release.yml` too (rejected: double publication race, see above). Replacing GitHub Actions outright (not asked; branch protection and `scripts/ci-build.sh` depend on GitHub's runs).

## Evidence

`depot ci migrate preflight` reported the Depot Code Access app installed for 5omeOtherGuy/phaseone. `diff .github/workflows/X.yml .depot/workflows/X.yml` shows only the header comment and the `runs-on` label. `gh secret list` and `gh variable list` for the repo are empty, so `depot ci migrate secrets-and-vars` had nothing to import.
