# ADR-0181: The MCP client is a host port with one native foundation adapter, and its tool generations are journalled

## Context

p1 cannot use external tool servers (seams catalog, family 7, rank 6). The owner approved the MCP seam design attached to #695 on 2026-10-10 (ADR-0153, decision 9), and the dispatcher ordered the first slice as #792 on 2026-10-11 under the owner's delegation ("Decide it yourself"). The design calls for an `McpClient` port, one native adapter (`p1-mcp-client`, stdio and streamable HTTP), tools named `mcp__<server>__<raw>` with the identity `mcp:<server>` / `<raw>`, servers named per environment, and an MCP generation as the one deliberate, journalled exception to ADR-0103's fixed tool snapshot. #792 adds: no MCP SDK and no new crate (own JSON-RPC over existing workspace dependencies), a scrubbed child environment, results redacted and bounded through the output store, and the crate as `foundation` in the shipping audit. Three things this record settles are new contracts: the port, the crate's class, and the environment file's `[[mcp_servers]]` table.

## Decision

1. **Port.** `p1_contracts::mcp` holds `Transport` (`Stdio { command, args, env, cwd }`, `Http { url, headers }`), `McpClient::connect`, `McpServer::{tools, call, resources, read_resource}`, `RemoteTool`, `RemoteResource`, `ResourcePage`, `ContentBlock` and `McpError`, as in the #695 design with two adjustments: `Http.url` is a `String` the adapter checks (p1-contracts takes no `url` dependency), and a result the server marks `isError` is `McpError::ToolFailed { content }`, so `call` keeps the design's return type. `Transport::Stdio.env` is the child's whole environment.
2. **Adapter.** `p1-mcp-client` is the one adapter: newline-delimited JSON-RPC to a child (`env_clear` plus exactly the transport's `env`, its own process group so a Ctrl-C that interrupts a turn does not end it, stderr discarded, killed on drop) and streamable HTTP over `reqwest` (session id and protocol version headers, JSON or SSE answers through `p1-provider-http`'s portable `SseDecoder`, no redirects). It answers a server's `ping` and refuses every other server request. It is `foundation` in `SHIPPING_TABLE`: a module can open neither a process nor a socket (ADR-0081), and the tools it generates are bridges to a server, not extension implementations with a module twin. Zero native fallbacks stays true.
3. **Generation.** At session start the host connects every server the environment names (one retry per server, bounded by a timeout), and `ToolGenerations` builds generation 1: one `McpTool` per served tool, `Effect::ReadOnly` when the server marks the tool `readOnlyHint`, `Effect::Executes` otherwise; a call is described as destructive unless the tool is read-only. A generation is built whole: a name clash, with another served tool or with a name the agent's assembly already uses, or a name no route can carry (more than 64 characters or outside `[A-Za-z0-9_-]`) fails it. `refresh` swaps the whole generation and keeps the previous one on any failure. The generation joins the main agent's assembled tools before the agent is built, wrapped by the same masking every assembled tool gets, so authorization (`AuthorizationPolicy`), redaction and the core's `Environment` record treat each tool as any other: the `Environment` record journals the generation and `ToolStarted` journals `mcp:<server>`. A later swap reaches an agent only through `Agent::reconfigure`, which commits a new `Environment` record; every other tool stays fixed at assembly (ADR-0103). A model switch or module reload keeps the session's generation, and fails on a name its new assembly already holds. The run's cancellation stops a session start that waits on a server. A result longer than 50 000 bytes shows its head and tail, and the whole text, masked before it is cut, goes to the session's output store (`OutputStore::store_text`, masked and capped like a command's output) with the `read_output` notice.
4. **Environment file.** `[[mcp_servers]]` entries name a server (`name`, lowercase letters, digits, `-` and `_`, at most 32, no `__`) and exactly one transport: `command` with optional `args`, `env`, `env_pass` and `cwd` (a relative `cwd` resolves against the workspace, which is also the default), or `url` with optional `headers` and `bearer_token_env`. The environment names servers, never their tools; a guest never names a server. A credential enters only by the name of one of p1's own variables (`env_pass`, `bearer_token_env`); a literal value with a credential shape, or an `Authorization` header, is refused at load. A stdio child gets the shell's allow-list (`ENV_ALLOW`, no credential among it), its `env_pass` variables and its literal `env`; every value passed by name is registered as a secret and masked. The table is validated with the rest of the file by `load_environment` and read by `load_mcp_servers`, because servers belong to the session, not to one agent's assembly.

## Consequences

Any MCP server reachable over stdio or streamable HTTP can serve tools to the main agent, under the same approval, masking and journal as a native tool, with no new external crate. A server that fails to connect, or a generation that cannot be built, fails the session start with an error naming the server: fail closed, as an unknown module does. Workers do not get MCP tools in this slice. Nothing triggers a refresh yet: `notifications/tools/list_changed` and a reconnect after a dropped connection are later slices, as are resources (`p1-module-mcp-resources` over an `mcp-resources` WIT capability) and per-ACP-session servers (#695). Image and audio content is named in the result text, not passed to the model, until attachments exist (#791). The SSE decoder's 1 MiB event limit bounds one streamed HTTP answer.

## Alternatives considered

An MCP SDK crate: refused by #792 (no new dependency). Generating the tools inside a WebAssembly module: a module can reach neither a process nor a socket, so the transport would still be native and the module would only proxy. Keeping `[[mcp_servers]]` in `EnvironmentFile`: it would add a field every constructor of that struct names, across many test crates, for data no agent assembly reads. Skipping a server whose tools clash or cannot be named: the agent would silently lack tools the environment asked for.

## Evidence

`cargo test -p p1-mcp-client` (fake server `src/bin/p1-mcp-test-server.rs` over stdio and over HTTP on 127.0.0.1: discovery with pagination, calls, `isError`, server ping, cancellation, the child-environment scrub, read-only hint to effect, clash refusal, invalid names, failed refresh keeps the generation, whole swap, bounded results); `cargo test -p p1-host --lib mcp::` (child environment, bearer token, one retry, clash with the assembly, masking); `cargo test -p p1-host --test mcp_servers` (a bash stdio server through the whole host: declared, called, masked, journalled); `cargo test -p p1-assembly --lib mcp_servers`; `scripts/check-module-boundaries.sh --shipping` (clean, `p1-mcp-client` foundation).
