# ADR-0079: Verified module releases and installation

## Context

ADR-0071 (DECISIONS.md D22) moves every tool, provider and policy of p1 into WebAssembly modules that
the native host loads by name, and says that until a later ADR decides otherwise "the host loads only
modules from p1's own release archive, verified by hash (ADR-0065 extended)". ADR-0065 defines the
release channel: after a green `gate` on `main` the release workflow publishes `main-<sha>` with the
binary, the share tarball (`environments/`, `routes/`, `profiles/`) and their checksums, and
`scripts/install.sh` verifies both checksums before it touches the prefix and swaps binary, updater and
share in one rollback transaction. ADR-0066 makes GitHub Actions the build farm; ADR-0077 moves builds
and the full gate onto the stream boxes and keeps GitHub-hosted CI as the merge gate.

A module release adds artifacts the checksums of ADR-0065 do not describe individually: component
packages, the WIT worlds and JSON schemas they were built against, the toolchain and runtime that built
and will run them, and the environment lock resolutions that name which package each shipped
environment assembles. Without one record binding them to the native binary, an installed prefix could
mix a binary with packages from another commit, and the loader's "verify then compile the same bytes"
rule (freeze item 6) would have nothing authoritative to verify against.

## Decision

The release archive carries a fourth root, `modules/`, and a release manifest binds everything a
release ships.

- `p1-share.tar.gz` holds `modules/manifest.json` and `modules/packages/…` beside `environments/`,
  `routes/` and `profiles/`. It never holds the repository's module sources, and no compiled-cache blob
  (`.cwasm` or any other precompiled artifact) is published or ever deserialized: the loader compiles
  the verified bytes itself.
- `modules/manifest.json` (format `p1-release-manifest/1`) records the source commit and tag, the
  native binary's asset name and sha256, the toolchain (rustc, cargo, the wasm target, `wasm-tools`,
  `wit-bindgen`) and runtime (wasmtime version and features) versions, the sha256 of every WIT file and
  every boundary JSON schema, the path and sha256 of every package file, every component digest, and the
  shipped environment lock resolutions. Unknown values are `null` and absent sets are empty arrays, never
  invented; the manifest is generated by `scripts/release-manifest.py` in the release workflow after the
  release binary is built.
- `scripts/install.sh` admits `modules/` as a fourth validated archive root and verifies the whole
  package set against the manifest — no missing, extra, duplicate, traversing, linked or mismatched
  entry, and a manifest whose native digest is the verified binary's — in its staging area before the
  installed prefix is touched. Binary, share data, updater and module set are replaced in the existing
  rollback transaction of ADR-0065, so a failure leaves the previous release whole. An archive without
  `modules/` (a release older than this ADR) still installs, so an explicit downgrade with
  `--from-release` keeps working. Once S1's metadata-only `p1 modules verify` exists, the installer runs
  it on the staged set before the commit; running sessions keep the module generation they loaded.
- Only packages named by the manifest of p1's own release are admitted (freeze item 6, F7); any other
  source is refused with an explicit error.
- ADR-0011 stands: `scripts/gate.sh` remains the single definition of green, and module builds,
  validation and the installer and CI-helper tests join that one gate rather than a second one.
  ADR-0043 stands: the terminal UI and its host driver stay native.

## Consequences

- An installed prefix is one release: the binary, its share data and its module set carry one commit
  and are verified against one manifest, so a mixed or tampered package set is refused before
  anything is replaced.
- Rollback and downgrade stay the ADR-0065 transaction: the module set lives under `share/p1/modules/`
  and moves with the share directory, so no second transaction exists.
- Before the freeze tag `wasm-boundary-v1` the manifest is a scaffold: the package, component and lock
  sets are empty and the pinned-tool fields are `null`; the slices after the tag fill them.
- The release workflow gains a generation step and a test (`scripts/test_release_manifest.py`); the
  installer's tests gain the module cases (missing module, corruption, interruption, old release).

## Alternatives considered

- One release asset per module package: rejected; publication and installation would have to keep
  many assets consistent, and a partial publication could not be told from a complete one.
- Publishing precompiled components to save load time: rejected by freeze item 6; the loader verifies
  and compiles the same bytes, and a compiled blob is code the manifest cannot vouch for.
- Signing the manifest: not now; ADR-0065's trust model (the public release channel over TLS plus
  checksums) is unchanged, and a signature can be added by a later ADR without changing the manifest's
  role.
