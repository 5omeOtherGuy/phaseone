# Usage ledger

The usage snapshot and renderer live in `p1-usage`, not the host or TUI: probing and layout must be reusable by both surfaces without coupling a provider to a UI. `p1 usage` supplies loaded, deduplicated routes, credential *source descriptions*, and p1-auth's credential references; it never carries credentials in the serialized snapshot.

## Data

`Snapshot { taken_at, routes }` has an RFC 3339 UTC timestamp and one `RouteUsage` per route. A route has id, label, source wording, `Probe` (`Supported`, `Unsupported`, or `Failed` with a credential/HTTP/network/parse kind), optional plan, windows, credits and extra usage, `observed_at` (when its values were fetched) and `stale` (the short failure reason when the host is showing a retained last-good snapshot). Each `Window` has a session/weekly/scoped/other kind, optional scope, percentage and reset time, a limit-reached flag, and optional vendor text (`detail`) that says more than the percentage does. `Credits` carries a balance and reset credits, and, when the vendor reports them, credits used/limit/currency (OpenRouter). Unknown measurements are `None`, never zero.

Coverage: the dashboard covers the six p1 route files (`anthropic-subscription`, `openai-codex-subscription`, `opencode-go-subscription`, `opencode-go-2-subscription`, `glm-subscription`, `kimi-coding-subscription`) plus the OpenRouter credits endpoint — seven sources. It does **not** cover OpenRouter model routing (credits only) or the free Muse Spark promo (no usage endpoint), and a provider with no usable credential still occupies a `no access` row rather than disappearing.

p1-auth alone resolves credentials; the probe makes one request with a 20-second timeout and no retries. Concurrent routes fail independently. HTTP errors retain only status and a restricted error code/type, not a body or headers. An API-key probe that is refused with 401 or 402 reports a credential failure; every other status keeps the HTTP kind, as the OAuth probes always did.

## Rendering contract

`render(snapshot, grid)` produces palette-independent lines and spans. Tone roles are INK (values and filled bars), DIM (labels), FAINT (unavailable rows), RULE (unfilled bars). The caller maps tones to ANSI or TUI palette. The grid rule right-aligns each value with computed padding at grid width (32 or 48); percentages fill rounded fractions of `grid - 6` cells, with both filled and unfilled cells rendered as `█`. Unknown values print `—`, never `0` or blank. No border or box-drawing. Supported routes rank by highest utilization, ahead of failures and unsupported routes. A window with vendor text shows that text where the percentage would go, and the bar below still carries the percentage; the text is compacted at parse time (`87/100 left`, the remaining count, not the used one) so a window label such as `5h` stays readable in the 32-column grid. A window whose percentage is unknown is never drawn as spent. Every route header carries its data age (`— · 12s`); a retained last-good value says `stale 2m (http 500)`, a provider with no usable access says `no access`, a failed probe with no data says `error · no data` followed by the sanitized failure, and a disabled extra-usage plan says `extra usage disabled`. The live frame's last row is the running binary's build hash and the snapshot time.

A future `USAGE` right-pane mode mounts the same lines at the pane's content grid and maps `Tone` to the SPEC §1 palette; no TUI change is needed to the module. The host's CLI maps the same roles to 24-bit terminal foreground colors.

## Watching from tmux

`scripts/usage-pane.sh [--replace] [SECONDS] [WINDOW_NAME]` (defaults `300` and `usage`, grid `48`) opens the ledger as a live tmux window so the owner can watch it outside a p1 session. It selects a window of that name when the current session already has one and creates it otherwise, running `p1 usage --watch SECONDS --grid GRID` — the `P1_BIN` binary (checked executable), else this checkout's `target/debug/p1`, else the main checkout's `<repo>/../phaseone-target/debug/p1`, else `cargo run -q -p p1-host -- usage --watch SECONDS --grid GRID`, and it prints which binary it chose. It is idempotent, and outside tmux it starts a detached session when no server is running and prints the `tmux attach` hint. In a terminal the watch frame uses the alternate screen and is fitted to the pane, so refreshes never grow scrollback and the terminal is restored on exit; a SIGWINCH redraws at once. `--replace` is the deployment path: it captures the existing window's scrollback to a file under `${P1_HISTORY_DIR:-$TMPDIR}` first, then clears history and respawns the window, so stale frames are preserved on disk and never kept on screen.

Non-goals: per-session cost roll-up from journals, OpenRouter model routing (its credits are shown, no model route exists), and the free Muse Spark promo (no usage endpoint).
