WHY NO CHECKBOXES
The plan reuses the transcript's own symbol set — ✓ done, ▪ working, · pending. A second notation for the same three states would be one vocabulary too many. The working row is the only line at full ink, so the eye lands on it without a highlight bar.
GOAL IS NOT A TODO LIST
/goal is host-owned and is never assembled as a tool, so the goal block is rendered as a quotation the agent is held to — not an editable checklist it can quietly rewrite.

THE ONE-LINE COMPROMISE
At 80 columns a single dim line appears under the composer carrying access mode, route, and context size. It is the only place this interface ever puts state at the bottom of the screen, and it exists because the ledger that normally holds those three values is gone.
WHAT DOESN'T CHANGE
Indentation, symbol set, and the two diff hues are identical at every width. Nothing reflows into a different shape — the interface only gets narrower.
11 — THE RIGHT PANE, DYNAMICALLY
Concept, not a contract — these four are sketches of what one pane can hold, in one design language. The pane has a mode, the mode follows what the session is doing, and the operator can always pin it. Width cycles off / 40ch / 56ch / split with ^W; ^Tab cycles the mode by hand.

^Tab to open
Most events do not deserve the whole pane. A two-line banner takes the top of the ledger, states the outcome and the key that opens it, and retires itself — the ledger underneath never moves. Anything still unresolved leaves a single counted line behind rather than a badge.
WHAT PROMOTES THE PANE
approval requested → DIFF, pinned
worker needs review → WORKERS, pinned
delegate spawns → WORKERS while live
output over 40 lines → PEEK, 3s
tool fails → PEEK, 3s
context over 60% → PEEK, 3s
nothing pending → LEDGER
TWO RULES THAT MAKE IT LIVEABLE
Pinning always wins. ^P pins the current mode and no event may swap it; what would have promoted itself waits as a counted line instead. A pane that changes under your hands while you read a diff is worse than no pane.
Only two states ever pin themselves — an approval and a worker waiting on review. Both are the session blocked on you, and both stay until you answer. Everything else peeks and retires.
STILL A MOCK-UP
These four modes are here to show that one pane, one symbol set and one pair of hues stretch across a context ledger, a log viewer, a diff reviewer and a worker dashboard without a second visual language appearing. Which modes ship, what they contain, and how promotion is timed are implementation choices — the constraint this section fixes is the vocabulary, not the feature list.
12 — HOUSE RULES
WHY A SECOND PANE
The ledger is not GUI chrome: no box-drawing, separated only by a background step, key-toggled, and gone below 100 columns. What it displays — budgeted context, spend, task diff — is the efficiency claim made visible, which is the one thing a second pane earns its width for. Unknown cost renders as —, never as zero.
NO BOTTOM STATUS BAR
Honoured everywhere except the 80-column fallback, where one dim line replaces the ledger it can no longer show. No CPU, no memory, no queue depth — three values that were already on screen a moment ago.
NO BRAILLE SPINNER
The working indicator is a three-cell LED chase in ink, which freezes to a static ▪▪▪ under P1_REDUCED_MOTION=1. Toggle it in the tweaks panel.
COLOUR NEVER CARRIES STATE ALONE
The two diff hues are the only colour in the interface and they always sit behind a + or − column. Strip every hue and the screens above still read correctly — success, failure, and approval are carried by ✓ ✗ !, never by green, red, or amber.
